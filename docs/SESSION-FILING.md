# Session-to-memory filing: first governed path

Status: local UI filing, connected-AI close operation, opt-in hook setup and session-end reminders are implemented and locally tested. Live client lifecycle acceptance remains unverified.

The local BrainLink Sessions screen now offers **File summary** when a stored session has a summary. The user chooses a destination vault and an existing folder in that vault, previews an episodic note, and explicitly saves it. Hidden, protected, excluded, nonexistent and symlinked folders are not offered or accepted. The user may remember the vault and folder for that exact project; BrainLink reuses that choice only while the folder still exists in the same vault. Similar project names never inherit it. The note inherits `private: true` regardless of the session's sharing toggle, carries the session ID and client as provenance, and remains `status: proposed` / `confidence: reported`. It never copies raw turns or promotes a summary to verified semantic knowledge. The note writer rejects credential-like content and never overwrites an existing note. The preview also proposes links to matching notes from the explicitly selected vault's privacy-filtered index; private, generated, excluded and other-vault notes are not candidates. Links are saved only when the user confirms the preview. Suggestions are reviewable associations, not proof that two claims are equivalent.

Connected agents can call `session_filing_folders` after identifying an explicitly enabled vault. It returns only existing, non-hidden, non-protected, non-excluded directories in that scope. `session_close` accepts one exact returned path; an invalid path is refused, and omission uses the configured intake folder. The close prompt directs agents to choose a clearly relevant existing folder or use intake when none fits, then preview before saving.

The filing screen first reuses a remembered vault/folder for the exact project when that folder still exists. Otherwise it may suggest a folder from an exact note-title mention in the summary, or from multiple matching public notes that cluster in one folder. It searches only the user-selected vault's privacy-filtered index, and abstains when exact mentions are split across folders or the similarity evidence is weak. The suggestion explains whether it came from a saved choice or related notes. It is never an automatic move: the user sees and can change the folder, previews the full note and links, and confirms before saving. A missing, inaccessible, read-only or excluded destination is not suggested. Similar project names never inherit remembered choices.

This path reuses the existing `proposeNote` write and attribution controls. The local API requires its Setup token. The preview and save actions require a chosen vault; neither an AI client nor filename matching silently chooses a personal, company, or client destination. The UI is available in English, Traditional Chinese, and Portuguese.

Connected MCP clients also have `session_close` and the `close-session` prompt. A client sends a stable task ID, explicit vault, title, goal, actual outcome and optional decisions, actions, corrections, open questions and next steps. A preview writes nothing. After approval or the user's close instruction, `confirm=true` stores a private summary-only session and a private proposed episode in that vault. The closure's client ID is deliberately distinct from imported Codex/Claude Code sessions, so the imported-session sharing switch cannot reveal it. Reusing a task ID is refused rather than changing an earlier outcome. This is an AI-reported summary, not an automatic transcript reader or a verified fact.

The session and vault note are two separate writes, not a transaction. If the session write succeeds but the note write fails (for example, concurrent filename creation or disk failure), the tool returns the failure with `session_saved: true`; the user can inspect the private session in the local UI and file it there. Do not claim both were saved unless `written: true` is returned. Simultaneous closes from separate BrainLink processes have not been tested for cross-process atomicity.

## Correct or withdraw a proposed episode

The Notes editor supports user correction of an episode body. Saving a changed body appends a dated `Summary corrected` entry to its existing `## Changelog` (or creates that section) and uses the store's full-etag compare-and-swap, so a concurrent edit is not overwritten. This history is an application receipt, not a cryptographic audit log; metadata-only edits are not separately annotated yet.

For a private note with `type: episode`, `status: proposed`, and a `source` matching `BrainLink session <id>`, the editor offers **Withdraw proposal**. It confirms before acting, changes only the status to `withdrawn`, retains the full summary, private flag and session source, and appends a dated changelog entry. It refuses unrelated sources, non-private notes, non-proposed notes, unsaved edits and stale revisions. Withdrawal does not delete the source session or erase the episode. This is reversible through the ordinary revisioned note editor, subject to vault write permissions.

Run `npm run test:all` for the core and UI-model suites. The note editor changes are local and have not yet received an installed-app/browser usability review.

Validation: `test/session-filing.test.mjs` and `test/session-close.test.mjs` use fictional company and personal vaults and verify preview-only behavior, private frontmatter and read blocking, chosen-vault-only writing, no overwrite, rejection of empty summary and secrets, exact-project vault and folder recommendations, folder exclusion/protection checks, API authentication, exclusion of raw private turns, a scoped MCP close, and non-exposure through the imported-session sharing switch. The link-isolation case confirms a public same-vault source can be previewed and saved while private same-vault and matching other-vault notes stay absent. Run with `node --import ./test/_preload.mjs --test test/session-filing.test.mjs test/session-close.test.mjs`.

## End-of-session integration boundary

Both Claude Code and Codex document local `SessionEnd` command hooks. Their hook payloads include a session identifier, working directory, reason, and transcript path. This makes a local end cue technically possible; it does not by itself produce a reviewed outcome summary or authorize saving one. BrainLink must not read transcript contents just because a lifecycle hook supplies a path. The opt-in command below records only a minimal local cue. Transcript ingestion would need a separate explicit setting, source-scope checks, secret filtering, and private-by-default storage.

Add this handler to the client's existing `SessionEnd` hook configuration (merge it with existing hooks; do not replace them):

```json
{
  "type": "command",
  "command": "brainlink session-end-cue --client claude-code"
}
```

The Sessions screen provides **Enable reminders** / **Disable reminders** for each client. Setup merges BrainLink's handler into user-level Claude Code settings or Codex hooks.json, backs up existing files, refuses malformed JSON, and preserves other hooks. Commands use absolute executable, script and application-data paths. Codex must separately review and trust the hook through `/hooks`; the UI labels configuration separately from verified runtime. No trust settings are modified. The `disconnect-all` command used by uninstallers removes only BrainLink's marked handlers.

Use `--client codex` for manual Codex configuration. The command reads hook JSON from stdin, discards `cwd` and `transcript_path`, and writes an idempotent cue under BrainLink's local application data. Reminders appear in the Sessions screen; **Dismiss reminder** hides one while retaining its local record. Duplicate deliveries do not revive dismissed reminders. The authenticated local UI receives the client and end time, an opaque cue identifier, and—only when there is exactly one exact same-client match in the existing local session index—an opaque BrainLink session reference. Matching reads session metadata only; it does not return the private summary or open transcript messages. **Review session** is an explicit user action that opens that one private session in the local UI; its reviewed summary then offers the existing **File summary** preview and confirmation flow. The client session ID, transcript path, working directory, and transcript contents are not included in the cue response. A missing or ambiguous match remains an unlinked reminder and fails closed. Run `brainlink session-end-cues` to inspect pending cues from the command line. Cues do not themselves generate or file summaries.

Validation: `test/session-hooks.test.mjs` checks merge/disable preservation, backups, idempotent installation, malformed-file refusal, authenticated controls, explicit boolean selection, and actual shell execution of generated commands over fictional data, including paths with spaces. `test/session-end-cue.test.mjs` checks minimal event storage, duplicate deliveries, private-field exclusion, exact unique same-client matching, an opaque session reference, private-summary withholding before the explicit review request, authenticated UI listing and retained dismissal. Browser review in an isolated fictional vault checked enable, trust guidance, dismissal and layout. See [UI evidence](evidence/session-closeout-ui.png). This does not replace a live client lifecycle test. Rollback: disable reminders in Sessions before reverting the change; saved cue records remain local.

A lifecycle cue or AI-reported summary alone is not a verified experience or long-term rule.
