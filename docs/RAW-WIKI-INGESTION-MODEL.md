# Raw-to-Wiki knowledge flow: reference review

Status: manual, daily, and repeated background polling scans exist. The user can poll selected folders at a 1, 5, 15, 30, or 60 minute interval while BrainLink is open. Local AI analysis and auto-filing remain separate opt-ins. The scanner supports Markdown, TXT, CSV/TSV, JSON, XML, YAML, LOG, HTML/HTM, PDF up to 100 pages, DOCX, XLSX, PPTX, and text-bearing PNG/JPEG/BMP images. HTML title and body text are parsed locally in a bounded worker. Scripts never run, linked resources are never fetched, and script/style/template/embedded content plus explicit hidden markup are omitted. External CSS is not evaluated, so text hidden only by an external stylesheet may still be extracted. PDF and Office extraction and image OCR run locally with bounded workers. A scanned PDF page with no selectable text is rasterized locally and OCR-processed; at most 10 such pages and 24,000 output characters are returned per PDF, and larger results are marked truncated. Image OCR uses bundled local English, Portuguese, and Traditional Chinese data and extracts text only. Legacy Word, other image formats, and other formats need separate extraction support. Non-Markdown inputs do not support Markdown frontmatter privacy flags, so their privacy boundary is the explicitly selected non-private vault/folder plus exclusions. Hidden paths, common OS metadata (`.DS_Store`, `Thumbs.db`, `desktop.ini`, `._*`) and Office temporary files (`~$*`) are skipped before opening. Agent reads use the exact queued source ID and revision. Polling rechecks only the configured folders; it is not an OS file-event watcher. Reviewed from Ian's supplied reel transcript and seven selected stills.

## Main idea

Keep original material intact, then let BrainLink build a separate, linked, easier-to-retrieve knowledge layer from it. The reel calls these `Raw` and `Wiki`, and adds a generated index, an append-only processing log, and automatic processing after new material arrives. Its goal is that agents use a compact map and follow relevant links instead of rereading the whole archive for each question.

This is a useful product direction for BrainLink. It complements the typed graph model in [GRAPH-KNOWLEDGE-MODEL.md](GRAPH-KNOWLEDGE-MODEL.md): the Raw/Wiki flow describes how knowledge is curated; typed graph edges describe specific relationships between approved records.

## What BrainLink already has

- User-owned Obsidian/Markdown vaults remain the source of truth; BrainLink does not require a fixed folder layout.
- Search, source links, related-note suggestions, a generated `BrainLink/Home.md` map, and ordinary Markdown links provide parts of the map-and-follow-links experience.
- Privacy and exclusions are applied before indexing and retrieval. Sessions are private by default; closeout uses review and confirmation.
- Activity records, backups, and RSI proposals provide pieces of traceability and recovery.
- Typed graph relations exist when explicitly recorded and verified; automatic entity and relation extraction is not implemented.
- `ingestion_queue` scans one explicitly selected folder in a non-private vault and returns metadata for new or changed supported sources. Setup can schedule or manually scan up to 20 such vault/folder targets together. In Setup, users choose existing folders from a vault-scoped picker instead of typing paths; the picker omits the vault root, hidden/protected/excluded folders and private vaults. Every target is checked independently for vault privacy, exclusions, symlinks, and file bounds. Hidden paths, common OS metadata (`.DS_Store`, `Thumbs.db`, `desktop.ini`, `._*`) and Office temporary files (`~$*`) are skipped before opening; the same rule applies to direct source reads. Markdown privacy and generated markers are checked from bounded frontmatter before its body is read. Non-Markdown files are covered by the selected non-private vault/folder and path exclusions, because those formats do not have Markdown frontmatter privacy flags. Private, malformed, excluded and BrainLink-generated Markdown notes are skipped. PDFs are signature-checked during scanning and extracted only when the exact queued source is opened. DOCX, XLSX and PPTX archives are checked for malformed, duplicate, encrypted, oversized, or path-traversing ZIP entries and extracted in bounded local workers. Office XML with DTD or entity declarations is rejected. XLSX extraction omits hidden sheets, rows and columns; PPTX extraction follows the visible slide list and omits hidden slides. PNG/JPEG/BMP dimensions and actual signatures are checked before OCR; recognized text is produced locally and capped at 24,000 characters. OCR language data is bundled into native installers, so file contents and language downloads are not sent to a cloud service.
- `ingestion_record` appends a local receipt for `filed` or `skipped`. A `filed` receipt requires a saved same-vault Markdown note outside the source folder that links to the source. The journal stores opaque IDs, hashes, outcome, time, scope hash and client label; it stores no title, path, note body or prompt.
- Profile-scoped agents need `search` for queue access and a separate `propose_note` grant to record a filing result.
- The portable `brainlink-raw-to-wiki` Agent Skill gives compatible clients the same safe sequence: read only selected queue items, search for duplicates, preview a linked note, wait for approval, then record the filed/skipped receipt. Canonical and Claude/Codex discovery copies are tested for parity.
- Clients that support MCP prompts can use `organize-sources` with one exact vault/folder pair. It processes up to five candidates per run and is listed for a scoped agent only when every required read, search, proposal and receipt permission is granted. The prompt does not itself approve writes; each proposal needs separate user approval, and receipts follow confirmed saves. Local tests verify both availability with the full grant and denial when the proposal grant is removed (commit `800e4e4`).

These points are based on repository code and local tests. Background scans can run daily at a chosen local time or poll every configured 1, 5, 15, 30, or 60 minutes; a user can also run all configured targets from Setup. Polling checks only the configured folders and does not watch filesystem events. With local Ollama enabled, each due scan can read and analyze up to five changed supported sources. By default, results stay in a private local review queue. A separate auto-file option saves new linked notes to an existing destination chosen for each source folder. Those notes remain `proposed` with reported confidence; BrainLink never edits or replaces an existing note or promotes generated content to verified knowledge. The tested auto-file path applies to scheduled and manual scans; live Ollama quality and installed-user experience have not been verified.

## Proposed BrainLink flow

1. **Keep the source.** New files and session records stay in their original, user-controlled location. Never silently rewrite or delete them.
2. **Check scope first.** Before reading file contents, classify the selected vault/profile and apply privacy, exclusion, client, and authorization rules. Unclear ownership or scope means skip and ask for review.
3. **Process only changes.** Use a content hash and source ID to identify new or changed material; avoid rereading and re-summarizing unchanged files.
4. **Prepare proposals.** Suggest a destination, concise knowledge note, source citations, entities, and typed relationships. Mark confidence and uncertainty. Update an existing knowledge note only through a diff or reviewable proposal.
5. **Review and apply.** Let users inspect, edit, approve, reject, or roll back proposals. Any future unattended mode must be separately enabled, narrowly scoped, and reversible; it must not change access policy.
6. **Refresh derived views.** Rebuild the index/map and graph from approved notes. Keep them generated and reproducible rather than treating the index as a second source of truth.
7. **Write a minimal event receipt.** Record source ID/hash, action, result, destination, time, and agent identity where available. Do not copy private text, secrets, prompts, or raw transcript excerpts into logs.
8. **Serve compact context.** Retrieve from the approved knowledge layer first; follow only authorized links relevant to the question. Include citations and measure answer quality alongside actual token counts.

The `Raw` and `Wiki` labels should be optional logical areas or profile-selected folders, not a forced two-folder migration. Users may keep their existing Obsidian layout and choose which folders are original inputs and which are AI-maintained outputs.

## Automation boundary

The reel suggests a file-drop hook or overnight schedule. BrainLink has an opt-in **daily scan** or a repeated background check every 1, 5, 15, 30, or 60 minutes for up to 20 selected folders, plus a manual **Scan now** action. Polling checks only the selected folder targets, not the whole vault. Scope and exclusions are checked before source text is read. Supported files are Markdown, TXT, CSV/TSV, JSON, XML, YAML, LOG, HTML/HTM, PDF up to 100 pages, DOCX, XLSX, PPTX, PNG, JPEG, and BMP. HTML title/body text is parsed locally in a bounded worker without executing scripts or fetching linked resources; script/style/template/embedded content and explicit hidden markup are omitted, while external CSS is not evaluated. PDF and Office document extraction and image OCR are performed locally; PDF pages without selectable text are OCR-processed up to 10 pages per PDF, and image OCR uses bundled English, Portuguese, and Traditional Chinese language data. OCR reads text only. If local Ollama drafts are enabled, PNG/JPEG bytes for a selected source may also be sent to loopback Ollama for visual description, requiring a vision-capable local model; BMP remains OCR-only. These image bytes are request-only and are not saved with drafts. All extracted output is capped at 24,000 characters and may be marked truncated. Office archives are checked for malformed, duplicate, encrypted, oversized, and path-traversing entries. XML parts containing DTD or entity declarations are refused. Hidden spreadsheet sheets, rows and columns, and hidden presentation slides are omitted from extracted text. Non-Markdown files have no frontmatter privacy marker and are covered by the selected non-private vault/folder and exclusions. With local Ollama enabled, each run can analyze up to five changed supported sources. Auto-filing is a separate opt-in; each scan folder needs an existing destination in the same vault. Saved notes are new, linked, `proposed`, and unverified. Scans run only while BrainLink is open; enable launch at sign-in if they should resume after login. A failed background scan is retried twice, 15 minutes apart, then waits until the next interval or day. Turning background scans off pauses future runs, and a manual scan remains available. OS event-based watching, legacy Word, other image formats, and other unsupported formats remain unsupported.

## How to prove it helps

Use fictional Personal, Organisation, and Client data, including planted private notes. Compare a baseline search flow with Raw-to-Wiki processing on frozen questions. Report:

- correct answers and citation/source accuracy;
- input tokens, separating provider counts from local estimates;
- time to retrieve and amount of repeated source reading;
- duplicate, misplaced, stale, or unsupported claims;
- privacy leaks in search, summaries, graph expansion, handoffs, and logs;
- recovery after a rejected proposal or rollback.

Do not call it a token-saving improvement if token use falls while answer quality, source coverage, or privacy worsens. The supplied reel is a conceptual reference, not evidence that the creator's implementation achieves these outcomes.

## Decision and remaining work

The scanner reuses the existing vault, local AI draft, and note-writing tools; it creates no parallel memory store. Existing tested behavior includes multi-folder daily, interval-polling, and manual scans; bounded retries; a review queue; and read-only source viewing. Local Ollama analysis is opt-in and capped at five changed supported sources per run; source content is checked for scope and revision, redacted, sent only to the loopback Ollama endpoint, and treated as untrusted input. PDF and Office parsing and image OCR happen locally before optional local Ollama analysis. Scanned PDF OCR is implemented with a 10-page limit, but cross-platform packaged OCR and real-world scan quality still need verification. Drafts persist in private BrainLink app data without storing the original body. The auto-file setting requires a selected destination for every target and saves only new linked notes as `proposed` with `confidence: reported`; tests confirm it does not overwrite existing files or mark generated knowledge verified. Live Ollama use, OCR accuracy on customer images or scans, usability and quality evaluation, cross-client behavior, legacy Word, other image formats, OS event-based watching, and measured token/time savings remain open.
