### Bounded cited context packets (2026-10-28)

Added the read-only `context_packet` MCP tool for query-focused retrieval. It reuses `vault_search` ranking, so vault scope, private-note filtering, and Twin semantic-memory policy run before packet formatting. Agents can cap results at eight sources and each excerpt at 300 characters; the default is four sources with full 300-character excerpts. Results carry exact vault-relative path, title, note date/status, validated confidence when present, and only include historical/truncation flags when applicable. The packet reports `not_in_brain` without inventing content; tool guidance tells agents to use `vault_read_note` for more text. On the frozen 30-case fictional retrieval set, default packets retained task success (17/30), source recall (1.000), and zero forbidden-source hits versus compact `vault_search`; estimated response size fell 27.5% (10,127 vs 13,966 tokens). The regression test covers this comparison, excerpt bounds, citations, empty results, private canaries, and Twin semantic grants. These are local token estimates and a source/context proxy; provider-billed savings and generated-answer quality remain unverified. Windows/Node.js 24.22.1 focused run across retrieval, core, profile, and response-metric tests passed 112 tests with 1 platform skip. Full suite has not been rerun after the packet default was tuned.
